# 银行客服培训系统 v1.0 设计方案

## 一、 设计原则与核心约束 (v1.0)
1. **外部知识库接入**：系统内部不维护向量数据库（如Milvus/Chroma）和文档解析切分逻辑，仅通过预留的标准化 HTTP API 接口调用外部现成知识库。
2. **单一模型与适配器模式**：v1.0 仅使用一个统一的大语言模型（LLM）底座。为未来扩展，设计统一的 LLM Adapter 层，便于后续切换或扩展多模型。
3. **本地化极简部署**：不使用 Docker/K8s 容器化，所有服务（前端、后端、数据库、缓存）均在本地物理机或虚拟机直接裸机部署。
4. **全链路日志收集**：在请求入口、路由分发、外部 API 调用、LLM 调用、业务逻辑执行等所有关键节点，实施严格的日志埋点和落盘记录。
5. **精简教学方法论**：v1.0 暂不引入费曼学习法、番茄工作法和 PBL 项目制，聚焦于核心的**“学（问答）、练（做题）、考（模拟）、评（打分）”**基础闭环。

## 三、 各模块详细设计与交互链路

### 1. 外部知识库接入模块 (External KB Client)
*   **设计思路**：系统不再包含 LlamaIndex 切分文档等逻辑。封装一个 `ExternalKBService` 类。
*   **预留接口设计**：
    *   `search_knowledge(query: str, top_k: int) -> List[dict]`：输入用户的搜索词，返回外部知识库的检索结果片段（Context）。
    *   `get_node_by_id(node_id: str) -> dict`：通过 ID 精确获取某个知识点的详情（用于 Quiz 关联出题）。

### 2. 统一大模型适配层 (LLM Adapter)
*   **设计思路**：将模型调用抽象化，当前只对接一个模型，但预留切换能力。
*   **接口设计**：
    ```python
    class BaseLLMClient:
        def chat_completion(self, messages: list, **kwargs) -> str: pass
        def chat_completion_stream(self, messages: list, **kwargs) -> Iterator[str]: pass

    class DefaultLLMClient(BaseLLMClient):
        # v1.0 的单一模型实现，待填入指定的模型 API
        pass
    ```
*   **日志埋点**：在基类中实现统一拦截，记录：`[TraceID] [ModelName] [Request Messages] [Response] [TokenUsage] [Latency]`。

### 3. Agent 核心功能与链路设计 (剥离复杂方法论)

#### A. Doc Agent (学 - 知识问答)
*   **功能**：解答考生关于银行业务的提问。
*   **交互链路**：
    1. 前端发送提问 `query`。
    2. Doc Agent 调用 `ExternalKBService.search_knowledge(query)` 获取参考上下文。
    3. Doc Agent 拼装 Prompt：`"基于以下知识库内容回答问题：{context}，问题是：{query}"`。
    4. 调用 LLM Adapter 进行流式输出。
    5. 返回给前端。

#### B. Quiz Agent (练 - 专项练习)
*   **功能**：根据指定知识点生成题目，并评估考生的回答。
*   **交互链路 (出题)**：
    1. 管理员/考生选择知识点 (通过外部 KB 接口获取)。
    2. Quiz Agent 拼装 Prompt 调用 LLM，生成单道情景题及标准答案，存入 PostgreSQL。
*   **交互链路 (答题与评估)**：
    1. 考生提交答案。
    2. Quiz Agent 将`标准答案`与`考生答案`发给 LLM，判断对错并给出解析。
    3. (注：v1.0 取消反向训练题生成等复杂机制，仅做单纯的判题反馈)。

#### C. Persona Agent (考 - 模拟实战)
*   **功能**：模拟不同性格的客户与考生进行单场景多轮对话。
*   **交互链路**：
    1. 考生选择一个场景（如：急躁型客户，处理转账失败）。
    2. Persona Agent 维护上下文 Memory (存储在 Redis 中)。
    3. 每轮对话，Persona Agent 结合系统 Prompt (包含客户性格设定) + 历史对话记录 + 考生最新回复，调用 LLM 生成下一句客户发言。
    4. 对话达到轮次上限或主动结束时，触发 Scorer Agent。
    5. (注：v1.0 取消 PBL 项目制多任务拆解，退回单目标对话模拟)。

#### D. Scorer Agent (评 - 评分与报告)
*   **功能**：对 Persona Agent 的整段模拟对话进行多维度评分。
*   **交互链路**：
    1. 获取完整的历史对话记录。
    2. 拼装 Prompt 要求 LLM 按 JSON 格式输出维度评分 (如：准确性、服务态度、合规性) 及评语。
    3. 解析 LLM 输出，落盘到 PostgreSQL，供前端展示。

### 4. 全链路日志收集方案 (Logging Design)
*   **Trace ID 机制**：每个前端发起的 HTTP 请求或 WebSocket 连接，均生成一个全局唯一的 `trace_id`，贯穿整条调用链。
*   **日志分级与落盘**：使用如 Python 的 `Loguru` 或标准 `logging` 模块。
    *   `access.log`：记录接口请求、响应状态码、IP、耗时。
    *   `llm.log`：专门记录所有模型调用的输入输出、Token 消耗，便于后续微调数据提取和费用核算。
    *   `agent.log`：记录 Orchestrator 路由决策、Agent 内部处理逻辑、外部知识库调用情况。
    *   `error.log`：记录所有的异常栈信息。
*   **日志格式规范**：统一采用 JSON 格式写入本地文件，方便日后直接被 ELK 或 Filebeat 等工具采集。
    ```json
    {"timestamp": "...", "level": "INFO", "trace_id": "req-123", "module": "LLMAdapter", "action": "chat_completion", "details": {...}}
    ```

### 5. 前端交互设计 (极简版)
*   **界面布局**：
    *   **管理员端**：
        *   知识库配置：仅提供对接外部知识库的参数配置页面（API 地址、Token等）。
        *   题库管理：查看 LLM 生成的题目并支持人工修改。
        *   人格管理：配置不同的客户系统 Prompt。
    *   **考生端**：
        *   学习大厅：直接搜索问答对话框。
        *   练习中心：选择知识点做题。
        *   考试中心：选择场景进入类似微信聊天的对话框。
        *   个人报告：查看历史考试得分。
*   **取消的功能**：界面中隐藏所有“番茄钟计时器”、“费曼复述按钮”、“项目制任务清单”组件。

## 四、 本地部署方案 (Local Deployment)

v1.0 阶段完全基于本地环境（无 Docker），需在部署机上提前安装好依赖环境。

1. **环境准备**：
   * 数据库：安装 PostgreSQL 14+ (本地运行)。
   * 缓存：安装 Redis 6+ (本地运行)。
   * 运行环境：Python 3.12+ (后端), Node.js 18+ (前端)。

2. **后端启动 (FastAPI)**：
   * 创建虚拟环境并安装 `requirements.txt`。
   * 配置 `.env` 文件（包含本地数据库连接、Redis连接、单一模型的 API Key、外部知识库的 URL 等）。
   * 通过 Uvicorn 裸机启动：`uvicorn app.main:app --host 0.0.0.0 --port 8000`

3. **前端启动 (React + Vite)**：
   * 安装依赖：`npm install`
   * 构建并启动本地服务：`npm run dev` (开发环境) 或 `npm run build && npm run preview` (生产环境本地托管)。

## 五、 数据模型关联 (ER 概要)

1. **User (用户表)**：区分 Admin 和 Trainee 角色。
2. **Question (题库表)**：关联外部知识库的 `node_id`，存储题目、标准答案、场景。
3. **Persona (人格表)**：存储不同客户类型的系统 Prompt 设定。
4. **ExamRecord (考试记录表)**：存储某次考试的整体得分、用时。
5. **ChatHistory (对话流水表)**：关联 ExamRecord，记录具体每一轮的对话明细（用于回溯和打分）。

## 六、 未来演进方向 (V2.0 规划)

在 V1.0 跑通基础的“学、练、考、评”闭环并实现数据落地后，V2.0 将重新引入高级教学法论，将其精准融入业务生命周期的各个阶段：

### 1. 【学】模块演进：融入番茄工作法与费曼学习法
*   **专注输入（番茄工作法）**：前端大厅引入“番茄陪练钟”。开启后进入 25 分钟专注学习模式，期间系统屏蔽干扰，只能与 Doc Agent 交互或查阅资料。
*   **强制输出（费曼学习法）**：番茄钟结束前，Doc Agent 角色反转，变为“提问的新手实习生”。学员必须用大白话向 AI 解释刚学的知识点。AI 通过语义理解判定其“听懂了”之后，该学习番茄钟才算完成，确保知识真正内化。

### 2. 【考】模块演进：融入 PBL 项目制与反循环机制
*   **场景连贯（PBL 项目制学习）**：将单点的题目升级为连环剧本（如“处理老年人遭遇电信诈骗项目”）。数据库新增 `Project` 表，串联多个 Persona 节点。考试不再是单句应答，而是全流程的业务处理。
*   **动态施压与防套话（反循环机制）**：引入意图/套话检测拦截器。如果学员在考试中连续多次使用无效的“车轱辘话”（如“请您理解”），AI 考官（Persona）将触发愤怒机制，强制打断套话循环，逼迫学员给出实质性解决方案。

### 3. 【练】模块演进：融入错题反循环机制
*   **弱点刻意练习（反循环机制）**：基于记忆曲线的错题重推。数据库新增 `User_Weakness`（用户弱点标签表）。当学员在考试中某项指标（如合规性）得分较低时，Scorer Agent 会打上弱点标签。次日进入练习中心时，Quiz Agent 会根据弱点标签，变换场景（如换一种诈骗场景）动态生成题目，要求学员反复刻意练习，直至形成正确的业务肌肉记忆。
