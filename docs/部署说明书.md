# 智能客服陪练系统 · 部署说明书

> 版本：v1.0 · 适用于 macOS / Linux 开发环境部署

---

## 一、系统简介

智能客服陪练系统是一套面向银行客服培训场景的智能化平台，结合大语言模型（LLM）、向量检索（RAG）、知识图谱与项目制学习（PBL），实现 **学员练习 → 错题分析 → 反向训练 → 模拟考试 → 能力画像** 的闭环训练流程。

### 核心功能
- **学习大厅**：银行业务知识库问答（RAG）、费曼复述、番茄钟
- **练习中心**：按业务线分类的题目练习、教学题型、反向训练（错题变种）
- **理论考试**：管理员组卷、发卷、学员作答、详情查看
- **情景模拟**：动态模拟考试，客户人格 + 烦躁值机制 + PBL 项目制
- **管理后台**：用户/题库/人格/知识库/知识图谱/项目场景/数据大屏管理

### 技术栈
| 层级 | 技术 |
|---|---|
| 前端 | React 19 + Ant Design 6 + Vite 8 + Recharts |
| 后端 | Python 3.12 + FastAPI + SQLAlchemy 2.0 (async) |
| 数据库 | MySQL 8.x（生产）/ SQLite（备选） |
| 缓存 | Redis 5+（可选） |
| 向量库 | ChromaDB（本地持久化，离线模式） |
| 全文索引 | Whoosh |
| LLM | 阿里云百炼 · DeepSeek 系列（v3.2 / r1-distill-qwen） |
| Embedding | paraphrase-multilingual-MiniLM-L12-v2 |

## 四、MySQL 数据库配置

### 1. 安装并启动 MySQL（macOS 示例）

```bash
# 使用 Homebrew 安装
brew install mysql@8.0

# 启动 MySQL 服务
brew services start mysql@8.0

# 首次登录（无密码）
mysql -u root

# 在 MySQL 中设置 root 密码为 123456（开发环境）
ALTER USER 'root'@'localhost' IDENTIFIED BY '123456';
FLUSH PRIVILEGES;
EXIT;
```

### 2. 创建数据库

```bash
mysql -uroot -p123456 -h127.0.0.1 << 'EOF'
CREATE DATABASE IF NOT EXISTS customer_service
  DEFAULT CHARACTER SET utf8mb4
  DEFAULT COLLATE utf8mb4_unicode_ci;

SHOW DATABASES;
EOF
```

### 3. 配置数据库连接

编辑项目根目录 `.env` 文件（如不存在则创建）：

```bash
# 项目根目录 .env
DASHSCOPE_API_KEY_ENC='你的加密API Key'
```

编辑 `backend/app/core/config.py` 确认数据库连接字符串：

```python
# backend/app/core/config.py
DATABASE_URL: str = "mysql+aiomysql://root:123456@127.0.0.1:3306/customer_service"
REDIS_URL: str = "redis://127.0.0.1:6379/0"
```

**连接字符串说明**：
- 格式：`mysql+aiomysql://用户名:密码@主机:端口/数据库名`
- 默认：`root:123456@127.0.0.1:3306/customer_service`
- 如需切换 SQLite（开发备选）：`sqlite+aiosql:///./backend/local.db`

### 4. 初始化数据库表结构

```bash
# 确保已激活虚拟环境
source venv/bin/activate

# 执行初始化脚本（自动创建所有表，不会清空已有数据）
cd backend
python init_db.py
cd ..
```

**预期输出**：
```
正在初始化数据库...
数据库初始化完成！
```

## 五、LLM API Key 配置

系统使用 **Fernet 加密** 存储 API Key，避免明文泄露。

### 1. 生成加密密钥

```bash
source venv/bin/activate
python3 -c "
from cryptography.fernet import Fernet
key = Fernet.generate_key()
with open('.secrets.key', 'wb') as f:
    f.write(key)
print('密钥已生成到 .secrets.key')
print('请妥善保管，切勿提交到 git')
"
```

### 2. 加密 API Key

```bash
python3 -c "
from cryptography.fernet import Fernet
with open('.secrets.key', 'rb') as f:
    key = f.read()
f = Fernet(key)
api_key = input('请输入你的 DASHSCOPE API Key: ').strip()
enc = f.encrypt(api_key.encode()).decode()
print()
print('将以下内容添加到 .env 文件：')
print(f'DASHSCOPE_API_KEY_ENC={enc!r}')
"
```

### 3. 写入 .env

将上一步输出的内容写入项目根目录 `.env`：

```bash
# .env
DASHSCOPE_API_KEY_ENC='gAAAAABm...你的加密字符串...='
```

### 4. 模型配置

系统在 `backend/app/services/llm_adapter.py` 中配置了 4 个模型：

| 别名 | 模型名 | 用途 |
|---|---|---|
| `reasoning` | deepseek-r1-distill-qwen-7b | 推理任务（评分、分析） |
| `chat` | deepseek-v3.2 | 对话任务（客户回复、文档问答） |
| `fast` | deepseek-v4-flash-flash | 流式输出 |
| `r1` | deepseek-r1 | 默认推理模型 |

调用方式：
```python
await llm_client.async_chat_completion(messages, model="chat", timeout=120)
```

## 六、知识库初始化

系统使用 ChromaDB 作为向量知识库，首次启动会自动从 `backend/data/mock_kb.json` 导入知识节点。

### 1. 准备知识库数据

确保以下文件存在：
- `backend/data/mock_kb.json` - 原始知识节点数据
- `backend/data/chroma_db/` - ChromaDB 持久化目录（首次启动自动创建）

### 2. 启动时自动初始化

后端服务启动时，`ExternalKBClient.__init__` 会检测 ChromaDB：
- 如果 collection 已有数据 → 跳过初始化
- 如果 collection 为空 → 读取 `mock_kb.json` 并向量化导入

### 3. 手动导入自定义知识库

如需从 Markdown 文档生成知识库：

```bash
source venv/bin/activate
python generate_kb.py 输入文档.md 输出.json
# 然后将输出.json 内容合并到 backend/data/mock_kb.json
# 删除 backend/data/chroma_db/ 目录后重启服务，触发重新向量化
```

### 4. HuggingFace 离线模式

为避免 Embedding 模型在线检查导致启动超时，**必须**设置环境变量：

```bash
export HF_HUB_OFFLINE=1
export TRANSFORMERS_OFFLINE=1
```

`start_prod.sh` 已自动设置。

## 七、启动服务

### 方式一：使用启动脚本（推荐）

```bash
# 确保已赋予执行权限
chmod +x start_prod.sh

# 启动
./start_prod.sh
```

`start_prod.sh` 会依次执行：
1. 设置 HuggingFace 离线模式
2. 初始化 MySQL 数据库表结构
3. 启动后端 FastAPI 服务（端口 8000）
4. 启动前端 Vite 开发服务器（端口 5173/5174）

### 方式二：手动分别启动

**启动后端**：
```bash
source venv/bin/activate
export HF_HUB_OFFLINE=1
export TRANSFORMERS_OFFLINE=1
cd backend
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

**启动前端**（新终端）：
```bash
cd frontend
npm run dev
```

### 方式三：生产构建前端

```bash
cd frontend
npm run build
# 生成 dist/ 目录，可由 nginx 或 FastAPI 静态文件服务托管
```

## 十一、常见问题排查

### 1. 后端启动失败：`ModuleNotFoundError`

```bash
# 确保激活虚拟环境
source venv/bin/activate

# 重新安装依赖
pip install -r backend/requirements.txt
pip install aiomysql chromadb whoosh sentence-transformers
```

### 2. 数据库连接失败：`Access denied for user`

```bash
# 检查 MySQL 是否运行
brew services list | grep mysql

# 检查密码是否正确
mysql -uroot -p123456 -h127.0.0.1 -e "SELECT 1;"

# 确认 customer_service 数据库存在
mysql -uroot -p123456 -h127.0.0.1 -e "SHOW DATABASES;"
```

### 3. ChromaDB 初始化失败：`HuggingFace network error`

```bash
# 必须设置离线模式
export HF_HUB_OFFLINE=1
export TRANSFORMERS_OFFLINE=1

# 首次运行需要在线下载 Embedding 模型，可临时取消离线模式
unset HF_HUB_OFFLINE TRANSFORMERS_OFFLINE
# 启动一次后端，让模型下载完成
# 下载完成后再设置离线模式
```

### 4. LLM 调用失败：`API Key 未初始化`

```bash
# 检查 .env 和 .secrets.key 是否存在
ls -la .env .secrets.key

# 重新加密 API Key（参见第五节）
```

### 5. 前端无法访问后端 API：CORS 错误

后端已配置允许所有跨域请求（`allow_origins=["*"]`）。如仍有问题：
- 检查 `frontend/.env` 的 `VITE_API_BASE_URL` 是否正确
- 确认后端服务已启动：`curl http://localhost:8000/api/v1/health`

### 6. 前端端口冲突

Vite 默认使用 5173，如被占用会自动切换到 5174。查看终端输出确认实际端口。

### 7. 业务线分类为空

系统启动时后台预热业务线分类。如首次启动较慢：
```bash
# 手动触发分类
curl -X POST http://localhost:8000/api/v1/admin/kb-nodes/auto-classify
```

## 十三、数据备份与迁移

### 1. MySQL 数据备份

```bash
# 导出全部数据
mysqldump -uroot -p123456 customer_service > backup_$(date +%Y%m%d).sql

# 恢复数据
mysql -uroot -p123456 customer_service < backup_20260720.sql
```

### 2. ChromaDB 向量库备份

```bash
# 直接打包目录
tar -czf chroma_db_backup.tar.gz backend/data/chroma_db/

# 恢复时解压到原位置即可
```

### 3. 切换数据库（MySQL ↔ SQLite）

修改 `backend/app/core/config.py`：

```python
# MySQL
DATABASE_URL: str = "mysql+aiomysql://root:123456@127.0.0.1:3306/customer_service"

# SQLite（开发备选）
DATABASE_URL: str = "sqlite+aiosql:///./backend/local.db"
```

切换后需重新执行 `python init_db.py` 初始化表结构。

## 十四、安全注意事项

1. **`.secrets.key` 和 `.env` 切勿提交到 git**，建议加入 `.gitignore`
2. 生产环境务必修改 `SECRET_KEY`（`backend/app/core/config.py`）
3. 生产环境 MySQL 密码不要使用 `123456`
4. CORS 配置 `allow_origins=["*"]` 仅用于开发，生产应指定具体域名
5. LLM API Key 有调用费用，注意监控 `backend/logs/llm.log` 中的 token 消耗
